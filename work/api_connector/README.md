# Автоматическое обновление зарплатного дашборда

Обновление выполняется обычным Python-кодом без AI: API-загрузка, дедупликация, правила релевантности, географии и зарплат, затем пересборка HTML.

## Запуск вручную

```sh
python3 work/api_connector/refresh.py
```

Команда обновляет Headcount Labs, SuperJob, «Работу России», открытые RSS/Telegram/API-источники и выбранные публичные доски работодателей в Greenhouse, Lever и Ashby, берёт справочный курс USD к CHF/GBP/RUB и пересобирает `outputs/salary_dashboard.html`. При ошибке сохраняется предыдущий снимок курса и источников. Ключи читаются только из `.env` и не попадают в HTML.

Чтобы обновить только курс и не делать запросы к API вакансий:

```sh
python3 work/api_connector/refresh.py --fx-only
```

To refresh public RSS, Telegram, and employer ATS sources without repeating the credentialed APIs or the slower legacy job-board collectors:

```sh
python3 work/api_connector/refresh.py --public-only
```

## Расписание macOS

`install_schedule.sh` устанавливает LaunchAgent на каждый понедельник, 09:00 по локальному времени. Он запускает тот же `refresh.py`. Нужны активная учётная запись пользователя и доступ к сети. Логи хранятся в игнорируемой Git папке `logs/`.

```sh
work/api_connector/install_schedule.sh
```

## Правила данных

- Headcount Labs, SuperJob и «Работа России» обновляются еженедельно. «Работа России» запрашивается по четырём узким запросам C++ и не требует ключа; поля зарплаты без периода не попадают в месячные или годовые сравнения.
- Публичные источники: до 16 досок работодателей Greenhouse/Lever/Ashby, восемь Telegram-превью, RSS HeadHunter и Habr Career, Reed, SwissDevJobs, ictjobs.ch и DevITjobs UK, API Himalayas и Active Vacancies, а также бесплатные фиды YubHub. Reed опрашивается по публичным поискам Лондона. Habr Career подключён через публичный RSS; вакансии проходят те же кодовые фильтры C++/senior и строгую дедупликацию. Jooble API, Careerjet API и Techmap API подключены в коде, но начинают сбор только после добавления соответствующих GitHub Actions Secrets: `JOOBLE_RU_API_KEY`, `JOOBLE_UK_API_KEY`, `JOOBLE_CH_API_KEY`, `CAREERJET_API_KEY`, `CAREERJET_USER_IP`, `TECHMAP_RAPIDAPI_KEY`. Jooble выдаёт отдельный ключ на страну; Careerjet требует ключ издателя и IP/UA в запросе. У Techmap запрос ограничен тремя рынками за обновление и 15 запросами в месяц — внутри бесплатной квоты 100; это защищает от платного превышения даже при нескольких ручных запусках. Не выбирайте платный тариф. CV-Library не включён: его API требует партнёрского одобрения и не рассчитан на массовое скачивание. JobCloud требует одобрения партнёрского фида; у ITBoard не подтверждён разрешённый автоматический интерфейс; developerjobs.ch запрещает сбор и повторную публикацию сайта как датасета. Лента ictjobs.ch ограничена десятью последними публикациями; фиды YubHub — ста вакансиями каждый и требуют атрибуции. JobServe подключится после добавления секрета `JOBSERVE_RSS_URL` с RSS-ссылкой сохранённого London C++ поиска. C++ вакансии из DevITjobs UK учитываются только при явном London location и дате публикации не старше 90 дней; Hiring Index при наличии ключа опрашивает до 300 строк за один запуск (до 1 500 строк за пять еженедельных запусков) в пределах бесплатной месячной квоты 2 500 результатов. Широкая удалённая вакансия не относится к Лондону без подтверждения London-based.
- Telegram-публикация не подтверждает, что вакансия ещё открыта; свежесть оценивается по дате поста, поэтому закрытые объявления могут сохраняться до 90 дней. Telegram-зарплата без явного периода не попадает в расчёт; несколько вилок для разных грейдов в одном посте не объединяются. HeadHunter RSS прекращает запросы при блокировке и не обходит CAPTCHA или ограничения доступа.
- Курсы USD к CHF/GBP/RUB берутся из ExchangeRate-API; сам источник обновляет таблицу раз в день, наш снимок обновляется вместе с еженедельным сбором. На дашборде есть обязательная ссылка-атрибуция.
- YubHub разрешает бесплатное повторное использование открытых фидов с атрибуцией; в карточке вакансии сохраняется прямая ссылка работодателя, а на дашборде указывается источник. Active Vacancies публикует бесплатный API для research/dashboard, требует сохранить ссылку на первичное объявление и ссылку на Active Vacancies.
- Переключатель периода пересчитывает годовые суммы в месячные и обратно множителем 12; дневные ставки остаются дневными.
- Adzuna — конечный снимок пилота включён в кодовый обзор, но не опрашивается повторно. Зарплаты с `salary_is_predicted` считаются отдельно и не входят в вилки; остальные учитываются только при явной сумме с локальной валютой, периодом и подтверждённой дате сбора источника. Для нынешнего пилота дата сбора неизвестна; время пересборки её не заменяет.
- API-записи проходят кодовые правила для C++, seniority, активного статуса, локального рынка и формата зарплаты. Senior определяется явным названием либо опытом с нижней границей от 5 лет; предпочтения и диапазон 2–5 не являются минимумом 5. Прогноз Adzuna блокируется до любых fallback.
- Зарплата учитывается только при совпадении локальной валюты и явного периода. Бонусы и total compensation не подменяют базовую оплату. Границы объявлений показываются от пяти групп одного формата (валюта/период/налоги/состав/тип найма); это не гарантия независимости или репрезентативности. Неизвестные параметры не угадываются.
- Верхние карточки дашборда основаны на отдельно проверенном статическом срезе; они не обновляются этим расписанием. Живой блок API внизу обновляется еженедельно.
- Adzuna остаётся старым пилотным снимком внутри этого блока, поэтому его дата не меняется при очередной еженедельной пересборке.

## Проверка и аудит

`python3 -B -m unittest discover -s work/api_connector -p test_statistics.py` — офлайн-регрессии. После `finish.py` запуск `node work/salary_dashboard_publish/test_display.js` проверяет подписи периода/масштаба и область фильтров без браузера.

`outputs/salary_api_audit.json` и раскрытие под API-таблицей содержат исходные URL/ID, зарплатные свидетельства и причины исключения. Фильтры сегмента и уровня действуют на API и статический блок. API-сегмент определяется словами из описания и названия; это кодовая классификация, не ручная проверка.

`refresh.save_and_build` сохраняет неизменяемые исходные снимки в `data/snapshots/` до замены latest; существующий источник сохраняется при неуспешном сборе. История начинается с первого сохраненного снимка; месячные изменения пока не рассчитываются.
